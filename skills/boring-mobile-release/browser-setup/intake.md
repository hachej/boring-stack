# Browser setup: information to collect

Copy this structure into a private task record, not this public repository. Fill
from verified project configuration and the account owner. Unknown means unknown;
never invent an address, D-U-N-S number, compliance answer or review login. Collect
missing ordinary fields together; request sensitive information only when needed.
Use secret references for credentials and a private approved destination for files.

## Owner and organization

| Information | Where used / source |
|---|---|
| Account type: individual or organization | Owner decision; determines seller identity and verification flow |
| Legal entity name, country and registered postal address | Official company records; enrollment/payment/verification, distinct from marketing name |
| D-U-N-S number if required | Verified organization record; do not substitute tax/company registration number |
| Organization website and domain work email | Enrollment and organizational verification |
| Authorized person's legal name, role, work email, reachable phone | Owner-provided; signing authority must be true |
| Verification contact and authority evidence if requested | Owner-approved contact/document; do not send an unrequested message |
| Apple Account / Google account identifier | Existing owner account; verify selected organization before proceeding |
| Existing enrollment/order reference and current status | Private receipt or portal; avoid duplicate purchases/enrollments |
| Identity/company documents if the portal requests them | Owner-supplied; record only private file reference and upload authorization |
| Payment method and fee/currency shown by portal | Owner handles or explicitly authorizes according to tool policy; never store card data here |
| Trader status and public contact details for chosen markets | Owner-confirmed; verify what the storefront will disclose |

## App identity and listing

| Information | Value requirements |
|---|---|
| Display name and primary language | Product-approved, store length/availability checked |
| iOS bundle ID / Android application ID | Exact release configuration, stable and owned; never derive from a temporary label |
| Apple team ID / Google developer account | Verified account selector, not inferred from email alone |
| Apple SKU | Unique internal identifier, recorded privately with app ID |
| App or game; category and tags | Actual functionality |
| Free/paid download; in-app products/subscriptions | Explicit commercial decision; do not confuse free download with no in-app purchases |
| Target countries, platforms and devices | Requested scope; avoid automatically enabling every region |
| App descriptions and localized release/test notes | Match implemented functions; no unsupported health or privacy claims |
| Support email/URL, privacy URL, marketing URL if used | Working public pages; correct responsible entity |
| App icon, screenshots and feature graphic where required | Approved real app assets; validate current console dimensions per slot |
| Copyright/rights information | Owner-confirmed rights to submitted content |
| Review access | Dedicated non-production-data review account, instructions and any special access prerequisites |

## Policy and testing inputs

Prepare a data inventory: data types, collection/use/sharing purposes, recipients,
tracking, link to identity, retention/deletion, encryption, permissions and SDKs.
Use it to answer App Privacy/Data safety, not a generic template. Collect factual
answers on ads, age audience, content rating, health/financial functionality,
account creation/deletion and export compliance. Ask for owner decisions where
facts do not determine the answer; record their source. Resolve payments rules
before describing checkout or selecting billing declarations.

Record the exact signed artifact path, checksum, source SHA, version/build, target
track/TestFlight group and intended tester audience. Tester identities are private;
only invite or notify the audience the user authorized. Record whether the request
is upload-only, distribute-to-testers, submit-for-review or public rollout.
